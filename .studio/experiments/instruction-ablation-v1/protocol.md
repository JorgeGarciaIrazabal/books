# Instruction comparison v1
Frozen before new outputs. Question: do three concise operational additions to story_architect, drafter and canon_keeper improve their assigned work against the current contracts? Two fresh synthetic fixtures cover fantasy and contemporary family comedy. The director designed treatments from observed prior failure categories but never uses the old test text as the new target. Fixture-specific answer keys are withheld.

Matrix: four requested exact model IDs, two supported effort settings each, current/proposed instruction arms. GPT-6.1 Sol and GPT-6 Sol use medium/high; author-selected Kimi low/high and verified Mistral none/high persist from the prior experiment. Each of 16 fresh candidate sessions returns six short artifacts (three roles × two fixtures), maximum about 1,800 words. No earlier artifact supplies later input. One substantive generation per cell; no choosing a better retry. Purely pre-generation failures may be repaired and logged.

Both arms use identical fixture, task, word budget, artifact schema and per-runtime system settings; only the three role contracts differ. Current contracts are copied before editing. Proposed contracts remain experimental until reviewed. All OpenCode roles use steps=2 with tools denied, avoiding the earlier steps=1 max-step contamination. That runtime correction applies to BOTH arms and is not attributed to the instructions. Codex uses bounded packet reads and exclusive writes. Native runtime system prompts still differ across providers.

Eight fresh reviewer sessions (the same two effort settings per model) see anonymous current/proposed pairs, counterbalanced left/right ordering, with exact-model pairs excluded. They see neither instruction arm nor model name nor earlier verdict. Each reviewer assesses 36 pairs (six eligible conditions × six tasks), allowing X/Y/tie with an exact short quote from each side and concise reasons. Same fixtures and rubrics apply. Reviewers must not replace quality judgment with mere compliance counting. No invented numeric literary scores.

Analyze within a model/effort/fixture/task before pooling. Average the two effort judgments within each reviewer model ID, then weight reviewer models equally; condition-level comparisons are retained. Summarize observed preference frequencies as preferences, not intrinsic quality scores. Report per-role and per-fixture changes, model interactions, disagreements and removal of one reviewer model. Independently audit timeline/capacity/custody/knowledge constraints and the four seeded errors plus six valid controls per audit. Report error/false-positive counts with denominators; these are objective fixture checks, not literary ratings.

Adoption rule set before outputs: a proposed role block is eligible only if its assigned phase has >50% updated preference in EACH fixture after equal model weighting, with no increase in its aggregate objective violations. If results split by fixture, regress on valid controls, or depend strongly on one reviewer model, retain the current live contract or make the proposed wording explicitly provisional with the dissent documented. Do not quietly revise a treatment after seeing its output. This tests an instruction PACKAGE, not the causal contribution of an individual sentence; bundled roles and adjacent tasks remain a confound. One generation per cell and two short fixtures cannot prove general or whole-book improvement. No model defaults change automatically.

All source hashes, conditions, blind mappings, raw native outputs, structured reviews and decisions are retained. No custom model client or agent runner: native Codex subagents and native OpenCode CLI only. Small offline scripts may prepare packets, audit artifacts and calculate recorded preferences. The director owns tasks/handoff. No canonical facts or manuscript are changed by these synthetic fixtures.
