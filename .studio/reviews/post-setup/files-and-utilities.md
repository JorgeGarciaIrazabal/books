## Actual bugs, in priority order

1. **P1 — An export-directory symlink can turn `build --replace` into source destruction.** `tools/studio.py:323` confines outputs to the whole book, while `tools/studio.py:334` writes through symlinked ancestor directories. `atomic_write` only rejects a symlink at the final file (`tools/studio.py:40`). Reproduced in a temporary scaffold: create chapters `manuscript/draft.md = FIRST` and `manuscript/other.md = SECOND`, list both in that order, replace the empty `exports/` directory with a symlink to `manuscript/`, then build with `--name draft --replace`. The first source chapter becomes `FIRST\n\nSECOND\n`, and a generated manifest appears in `manuscript/`. The command reports success. Minimal fix: reject a symlinked exports directory/ancestor that redirects export writes outside the real designated export directory; explicitly reject output paths aliasing source inputs. `--replace` authorizes replacing generated exports, not chapters. Add this regression.

2. **P2 — Default context files bypass path confinement and can include arbitrary external text.** `tools/studio.py:290` constructs default paths directly; only `--include` paths use `confined`. Reproduced by replacing a temporary book's `brief.md` with a symlink to a file outside the library: `packet --mode review` includes `EXTERNAL PRIVATE TEXT`, with no warning or failure. `check` would flag it, but packet does not run check and users may reasonably call it directly. Minimal fix: resolve every default input through `confined(book, name)` before reading, as with explicitly included paths. Test both an external link and a permitted ordinary file.

3. **P2 — A failed two-file build leaves a new output paired with no valid new manifest.** `tools/studio.py:334` writes Markdown before attempting the manifest at `tools/studio.py:335`, without preflight or rollback. Reproduced by creating `exports/draft.manifest.json` as a directory and running build with `--name draft --replace`: `IsADirectoryError` is raised, but `exports/draft.md` already exists. A filesystem failure on the second write can similarly replace an old output while retaining its old hash manifest. Minimal fix: preflight both targets before either write, prepare both contents first, and restore prior output/manifest state on an ordinary second-write failure. No general transaction framework is necessary. Add a fault-injected second-write regression that verifies the previous pair is preserved.

4. **P2 — Scaffold rollback can remove unrelated directories created by another task.** `tools/studio.py:150` snapshots every directory in the library, then `tools/studio.py:162` removes every new empty directory it finds after failure. Its comment claims these directories were created by this invocation, which is not established. Parent independently noticed this possibility; I verified it with fault injection: after scaffolding book one, wrap `atomic_write` for a book-two creation; on its fifth invocation create `book-one/research/new-notes/` to simulate unrelated concurrent work, then raise `OSError`. Rollback removes the unrelated `new-notes/` directory. It correctly restores the original series JSON and removes the failed book, so narrowing cleanup preserves the useful behavior. Minimal fix: track only directories actually created for this invocation's planned files, and clean only those; avoid library-wide cleanup. Test an unrelated concurrent directory surviving the injected failure.

5. **P2 — Valid JSON with the wrong top-level type crashes `build` instead of giving a controlled validation error.** `tools/studio.py:72` calls `.get` without requiring an object; `build` passes the result of `read_json` directly at `tools/studio.py:318`. `main` does not catch `AttributeError` (`tools/studio.py:371`). Reproduced with a temporary `book.json` containing `[]`: `main([...,'build',...])` raises `AttributeError: 'list' object has no attribute 'get'`. Existing-container manifests in `new_book` have the same unchecked `.get` pattern at `tools/studio.py:120`. Minimal fix: validate manifest object shape before using dictionary methods, returning a targeted `ValueError`; do not broadly swallow programming errors. Add wrong-type manifests to CLI error-path tests.

6. **P3 — Packet SHA-256 values are not hashes of the named source files when they contain CRLF newlines.** `tools/studio.py:298` uses universal-newline text reading, then `tools/studio.py:299` hashes the normalized string. Reproduced with `brief.md` bytes `first\r\nsecond\r\n`: the packet does not contain the actual file SHA-256. This makes snapshot comparison with `sha256sum` or build manifests disagree despite unchanged source files. Minimal fix: read bytes once, hash those bytes, then decode for presentation. A CRLF fixture is enough to cover this case.
